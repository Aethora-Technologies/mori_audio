# Mori Voice Input V0

本仓库为 Mori 心理陪伴大模型提供前端感知（Voice Input V0）的测试与联调基建。

## 1. 项目目前实现了什么
当前版本将纯算法实验推进到了可测量的工程化联调阶段，打通了"本地感知 -> 模型推理 -> 后端交互"的闭环：
*   **本地内存流式捕获**：基于 `sounddevice` 实现无磁盘 I/O 延迟的音频采样。
*   **离线 ASR 识别**：集成 Whisper (base) 实现 CPU 环境下的极速语音转文本。
*   **API 适配与联调基建**：内置 Mock Adapter，支持在无后端真实接口时进行单机断网开发。
*   **全链路 Latency 监控**：精确到毫秒级的 ASR 耗时与网络请求耗时打点。

## 2. Python 环境
*   **Python 版本**：推荐 Python 3.9 - 3.11
*   **硬件要求**：系统需配备并启用麦克风输入设备

## 3. 依赖安装
在终端中执行以下命令安装核心 Python 依赖包：
```bash
pip install sounddevice numpy openai-whisper requests
```
*(注意：Whisper 底层强依赖音频处理库，Windows 系统若出现找不到文件的报错，请确保已通过终端执行 `winget install ffmpeg` 安装并重启终端)*

## 4. 如何运行
直接在项目根目录运行主入口文件：
```bash
python mori_voice_client.py
```
启动后，系统将预热加载模型。出现提示后，敲击 `Enter` 键即可开启录音交互测试。

## 5. 配置 Mori API 的方法
接口配置统一在代码内部的 `Config` 类中进行集中管理：
*   **开发/单机模式（默认）**：若 `MORI_API_URL` 保持为空，系统将自动进入 Mock 模式，拦截请求并模拟后端返回，避免因网络问题阻塞前端调试。
*   **联调/生产模式**：将 `MORI_API_URL` 修改为 Mori 后端的真实接口地址（如 `http://<服务器IP>:<端口>/api/chat`），系统将自动发起标准的 HTTP POST 请求并处理超时与异常。

## 6. 当前已知问题 (Known Issues)
基于 V0 版本的 15 次真实口语化测试，当前系统存在以下亟待优化的痛点：
1.  **I/O 阻塞严重（VAD 缺失）**：当前采用硬编码的 5 秒固定录音策略。导致短句（如"好的"）产生长达数秒的无效等待，而长句会被生硬截断。
2.  **幻觉 (Hallucination)**：在录制到纯静音或强底噪时，Whisper 模型注意力失焦，会生成无意义的韩语、阿拉伯语等幻觉文本。
3.  **双语混合识别率低**：Whisper base 模型在缺乏 Prompt 约束时，面对中英夹杂或特定口音，容易发生同音字错译及强制输出繁体字。
